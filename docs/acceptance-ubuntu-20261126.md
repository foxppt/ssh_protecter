# Ubuntu 服务器验收记录（2026-11-26）

## 范围与环境

用户授权在一台 Ubuntu 服务器实际验收，并选择验收后保留安装、自行扫码绑定验证器。用户确认可使用 VNC 恢复；本次未通过 VNC 操作。

- Ubuntu 24.04.5 LTS，x86_64，Linux 6.8.0-151-generic。
- OpenSSH 9.6p1 Ubuntu-3ubuntu13.20，SSH 22，使用 `ssh.service` 与 `ssh.socket`。
- systemd 255.4-1ubuntu8.19，nftables 1.0.9。
- UFW 状态为 inactive，验收前 nftables 规则集为空。
- 时间由 systemd-timesyncd 同步；网页使用 服务器 IP 的 HTTPS 地址 和本机生成的 30 天自签名验收证书。
- 永久白名单保持空集合，IPv4/IPv6 保护开启，最终授权时长恢复为 5 分钟。

登录密码、验证器密钥、二维码和私钥不写入本记录。首先使用临时测试验证器完成自动化步骤；最后由用户执行重新绑定，替换为自己的验证器。

## 真实启动顺序和时钟保护

已核对重启前后 boot ID 不同，具体标识不公开。

来自 systemd 的本次启动单调时间：

| 单元 | 就绪时间 |
| --- | --- |
| ssh-protecter-guard.service | 5.905322 秒 |
| ssh.socket | 7.465246 秒 |
| ssh-protecter.service | 39.910170 秒 |

基础保护先于 SSH 监听器就绪。时间未同步时，授权服务明确拒绝恢复临时授权并退出，由 systemd 每 5 秒重试；本次重试 6 次后时间同步完成，服务才进入 ready。日志与 `NTPSynchronized=yes` 均已核对。

重启前后样本授权与封禁的截止时间戳分别保持一致。测试用回环封禁随后已清理；用户重新绑定撤销了剩余临时授权。

## 实测中修复的问题

1. 安装器原先只识别 Rocky 的 sshd 服务名，现增加对 Ubuntu ssh 服务名和 socket 的自动识别。
2. restorecon 现仅在工具存在时调用；SELinux enforcing 系统仍要求该工具，Ubuntu 不必额外安装它。
3. guard 默认服务依赖可能与早期 SSH socket 形成依赖环，现以 `DefaultDependencies=no` 在本地文件系统就绪后提前加载，实际重启顺序已验证。
4. 通用服务依赖 `time-sync.target`，不再强制请求不存在的 chronyd 单元。
5. 重启验收脚本同时识别 ssh/sshd 的 service 和 socket 名称。

用户自己的验证器已绑定，并已确认通过网页再次放行；已从外部重新取得 SSH 握手并以密码认证登录，网页到 SSH 的实际访问链路通过。

服务器现已升级为 `0.1.0-rc4`，包含 Ubuntu 部署修复和在线撤销临时授权命令。升级前后用户身份文件校验一致，原有授权截止时间未改变；未重新绑定或读取用户密钥。服务和 guard 已启用开机启动，验收用自动授权脚本已从服务器移除，保留测试日志供追溯。

撤销功能的 Linux 测试覆盖目标 IP 独立删除、IPv4 映射地址、IPv6、持久化重开后不恢复、巡检不恢复、内核失败后保持撤销，以及永久白名单冲突。服务器上以未获真实授权的测试地址 `192.0.2.250` 验证了 `revoke --ip` 的本地控制调用，原有用户 IP 授权保持不变；未擅自剔除用户实际使用的 IP。

自签名证书仅用于本次验收和当前 IP 地址访问，浏览器信任由用户手动处理。后续换正式证书可以通过现有重载流程完成。

本机未安装 Docker，未进行真实 Docker daemon 的运行时共存测试；已验证独立表管理和卸载不影响其他规则。服务器没有公网 IPv6 地址，IPv6 验收仅覆盖本机回环。上述结果不能代替 Rocky Linux 10、SELinux enforcing 或公网 IPv6 的专项验证。
