# 配置重载与失败恢复

[简体中文](reload.md) | [English](reload.en.md)

## 使用

编辑服务启动时指定的 YAML 配置，检查后重载：

```sh
ssh-protecter config-check --config /etc/ssh-protecter/config.yaml --resources
ssh-protecter reload
# 安装了本项目 unit 时，也可以：
systemctl reload ssh-protecter
```

`reload` 经 `/run/ssh-protecter/admin.sock` 的本地 Unix socket 向运行服务请求重载，并等待结果。目录 0700、socket 0600，仅本地 root 使用；服务自己读取原配置路径，不接受客户端上传配置或切换配置路径。自定义服务 socket 时，CLI 和 unit 的 `ExecReload` 必须指向同一地址。

CLI 成功退出代表配置已完成应用。重载失败返回非零退出码，systemctl 同样得到失败，不以“信号已发出”代替应用结果。若连接中断或客户端超时，结果可能未知，应检查服务日志后重试。该接口不提供 HTTP 公网入口。

## 可重载内容

- SSH 端口、IPv4/IPv6 保护开关、永久 IP 白名单。
- 后续授权使用的放行时长，以及验证失败统计窗口、次数和后续封禁时长。
- 可信代理范围。
- Go 直连模式的证书、私钥文件内容及路径。

已有授权、已有封禁记录的截止时间不变。扩大统计窗口只能统计仍被保留的失败记录，不会重建已清理的历史。变更端口或关闭某个地址族会减少对应的保护范围，应按实际 sshd 监听配置设置。

重载不改变 Go 的监听地址、TLS/代理运行模式或数据库路径。这些变更会在应用前被明确拒绝。

## 证书更新

外部续期工具更新证书文件后，在成功校验的前提下调用 `ssh-protecter reload` 或 `systemctl reload ssh-protecter`。程序先加载完整证书和匹配私钥，成功后通过原子指针发布；后续 TLS 握手使用新证书，已有连接保留。加载失败保留内存中的旧证书。

Nginx 模式仍由外部工具检查并重载 Nginx，本程序不替换 Nginx 的证书。证书加载检查不等价于证书链、域名或有效期验证，证书续期工具仍负责这些事项。

## 应用与回滚顺序

1. 严格解析和校验完整配置，准备证书。
2. 与授权和规则恢复取得同一把状态锁，拒绝当前不能热重载的字段。
3. 读取现有授权的原截止时间；生成新防火墙计划，内核校验后提交本程序规则。
4. 将新身份/基础规则/完整有效配置以一个私有文件持久化。文件 fsync、原子重命名和目录 fsync 构成磁盘提交步骤。
5. 发布内存配置和准备好的证书，返回成功。

配置文件、内核和进程内存没有共同事务。有效配置快照是崩溃恢复的提交点：快照提交前崩溃，启动恢复旧代次；快照提交后崩溃，启动恢复新代次。运行服务启动时先安装快照中的基础保护，再恢复临时授权。

应用失败时重新提交旧防火墙；持久化报错即使可能已经完成重命名，也会尝试重新持久化旧快照。确认回滚成功后保留旧服务；不能确认回滚成功时停止接受新授权，健康检查失败，由 systemd 重启后从磁盘快照恢复。此时日志明确说明故障，不能宣称旧配置一定仍然有效。

编辑中的 YAML 文件即使无效，也不会覆盖已提交快照。普通重启使用最后成功应用的完整配置，不偷偷激活之前被拒绝的文件修改。没有回写或删除管理员的 YAML 文件。

## 离线变更监听配置

需要切换直连/Nginx 模式或监听地址时，先停止授权服务（不停止 sshd），从本地 root 控制台执行：

```sh
ssh-protecter configure --config /etc/ssh-protecter/config.yaml
```

该命令获取与运行服务相同的跨进程写入锁，校验新配置及证书，提交规则和有效配置快照后退出。然后启动服务以使用新的监听方式。运行服务未停止时命令会失败，避免产生第二个写入者。失败按相同回滚逻辑处理。

数据库路径仍不允许直接变更，需另行完成数据迁移，避免意外清除封禁。不要删除身份快照或换一个空数据库绕过限制。

## 验证范围

当前通用测试覆盖：有效配置和持久化快照恢复、保持已有截止时间、内核应用失败、持久化错误及回滚错误、不可重载字段拒绝、并发授权/重载，以及真实本机 TLS 握手观察证书切换和坏证书保留。

Unix socket 完成确认与权限测试已在 AlmaLinux 10.1 WSL 执行，卡死恢复及其他故障覆盖见 `docs/operations.md`。目标机的 nftables、Docker、SELinux、整机开机及断电恢复仍需单独验收。当前环境 CGO 未启用，也未执行 Go race detector。
